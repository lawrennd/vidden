# CIP-0003: Present latent doodle space on the vidden explorer

## Summary

Present Baxter and Anjyo's *Latent Doodle Space* the same way we present
the stick man: a reconstruction **view** on the CIP-0002 **host**. Click
in the grey latent plot, see a doodle. Do not lead with a matplotlib
interpolation grid.

The GPy notebook on `notebook-latent-doodle-space` already packs
drawings, aligns strokes, and fits a GPLVM. That work stays a data
pipeline. This CIP is how we *show* the fitted space.

## Motivation

The doodle notebook tried to present the paper as (1) aligned examples,
(2) a correspondence check, (3) a grid of decoded stamps. The grid
looked the same in every cell when correspondence or the GP mean was
wrong, and there was no live latent space. People could not tell whether
alignment had worked.

The stick explorer already has the missing piece: training points on a
posterior-density image, a red cross for the current latent position,
click-to-track, leftover dimensions that persist. A doodle is another
`Y` row. It should use that host.

GPy CIP-000B left doodles out of scope until the explorer worked. The
explorer is in vidden. Doodles belong here, as a view, not back inside
GPy.

## Detailed Description

### What we present, and in what order

1. **Explorer first.** `panel serve examples/doodle.py --show` (or a
   Jupyter cell) opens the same layout as the stick demo: latent
   scatter, ARD bars, reconstruction pane. The reconstruction is a
   doodle. This is the paper's “click to synthesize.”
2. **Training family as context.** A row of the packed examples
   (faces, bugs, …) can sit above the explorer or in the README so we
   see what the points *are*. That row is static. It is not the live
   path.
3. **Correspondence is prep, not the demo.** Hungarian matching,
   arc-length resample, unmatched template strokes as NaN — that runs
   before we have a model. We do not put the matcher in the pointer
   loop. A notebook cell or a `load_family(...)` helper is enough.
4. **Generated faces with known factors first.** The GPy module can
   build cartoon faces from smile / roundness. Those let us check that
   a latent click moves the right parts. User-drawn families
   (`doodles/<family>/`) come after that path is honest.
5. **Drawing studio later.** `doodle_studio` on matplotlib GUI
   backends had the same macOS failure as `visualize`. Replacing it is
   a later CIP (Panel drawing pane, or Referia). This CIP loads
   families that already exist.

### View: `DoodleView`

MATLAB Visualise / Modify, as for the stick.

- **Visualise:** Bokeh `multi_line` (and optional joint scatter) from
  unpacked strokes. Freeze axis limits from the family's box (the
  generated faces use a fixed frame; user doodles use a cubic or
  padded box from the training set). Do not autoscale on modify.
- **Modify:** write `ColumnDataSource.data` from a packed `Y` row.
  Do not rebuild the figure.
- **Missing data:** NaN coordinates are unmatched template strokes.
  Skip those polylines. Do not draw them at the origin.
- **Closed strokes:** first point repeated at the end when the spec
  says closed.

Unpack is the inverse of the GPy pack: stroke specs give lengths;
the vector is concatenated `(x, y)` vertices.

### Host: parameterise what CIP-0002 already built

Do not copy `stick_explorer`. The host already assumes a view with
`.fig` and `.modify(y)`. Extract:

```python
latent_explorer(model, view, connect=None, ...)
```

`stick_explorer` becomes a thin wrapper that builds `StickView` and
calls `latent_explorer`. `doodle_explorer` builds `DoodleView` from
stroke specs and does the same.

Pointer, click-to-track, zeros-and-persist, ARD bars, Optimize, Bokeh
`Tap` / `context_menu` rules: unchanged. CIP-0002 still applies.

The reconstruction pane is the only part that knows about doodles.

### What does not move yet

| Piece | Stays | Why |
|---|---|---|
| Hungarian correspondence, resample, NaN packing | GPy doodle branch, or a later `vidden.doodle` prep module | Not a view |
| `doodle_studio` / `pick_doodles` | GPy doodle branch until a drawing CIP | Matplotlib GUI |
| Referia | Out of scope | Different host; pane split already allows it later |
| Interpolation *grid* as the main figure | Dropped as the lead demo | It hid the latent space |

A small grid of stamps can remain a notebook diagnostic after the
explorer works. It is not how we introduce the demo.

### Families

On disk, one directory per family: `doodles/faces/`, `doodles/bugs/`,
…. JSON strokes plus PNG thumbnails. The first selected drawing is
the template topology. That convention already exists on the GPy
branch. The explorer takes packed `Y`, stroke specs, and a model. It
does not own the filesystem layout.

## Implementation Plan

1. **Generalise the host** to `latent_explorer(model, view)` with
   stick as a wrapper. Tests: stick explorer still builds; view.modify
   is the only reconstruction write.
2. **`DoodleView`** from a packed row and `StrokeSpec`s. Tests:
   modify does not change axis ranges; NaN strokes omitted; closed
   loops close.
3. **`doodle_explorer` / `examples/doodle.py`** on generated faces
   (known smile / roundness). Same Optimize then click-to-track story
   as the README stick demo.
4. **README** section: how to run the doodle demo, and that the grid
   is not the point.
5. **Optional later:** load `doodles/<family>/` after alignment. Not
   required to close this CIP.

## Backward Compatibility

`vidden.host.panel.stick_explorer` keeps working. GPy doodle branch
unchanged until someone ports prep helpers. No Referia dependency.

## Testing Strategy

Geometry tests without GPy (pack/unpack, NaN skip, frozen limits).
Explorer construction `importorskip` Panel / GPy. No browser driver.
Manual: `panel serve examples/doodle.py --show` after Optimize.
