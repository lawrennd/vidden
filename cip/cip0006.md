## Summary

A **host** for Lawrence and Moore's hierarchical GP-LVM: a tree of 2-D
latent scatters. Click in a parent; the posterior mean writes the
children. Leaf nodes drive sub-skeleton reconstructions.

This is not another reconstruction view on `latent_explorer`. It is a
new layout. GPy `visualize.py` never had it. The original is MATLAB
`hgplvmHierarchicalVisualise`.

Stay Proposed until CIP-0004 (oil) and CIP-0005 (faces) are done. No
backlog until then.

## Motivation

Stick, doodle, oil, and faces are one latent plane plus one `Y` view.
HGPLVM is several GPLVMs wired as a tree: a parent maps to the latent
coordinates of its children; only leaves map to pose. The teaching
picture is the connected grid of scatter plots plus a composite
skeleton.

GPy has a hierarchical *kernel*, not this model and not this viewer.
Porting `lvm`/`image_show` does not give us HGPLVM. If we want the
ICML 2007 demo, we need this host.

## Detailed Description

### What MATLAB does

`~/lawrennd/hgplvm/matlab/hgplvmHierarchicalVisualise.m`:

1. Lay out one 2-D scatter per `model.node`, positions from
   `treeGetWidths` (depth × breadth), lines on a full-figure canvas
   between parent and child.
2. Click/move (`hgplvmLatentSpaceHandler`) on a node. Posterior mean
   at that `(x, y)` is the output `Y` of that node.
3. If the node has children, `Y` is concatenated 2-D coordinates, one
   pair per child; recurse.
4. If the node is a leaf, `Y` is the sub-skeleton; `skelModifyHierarchical`
   writes the pose on a shared 3-D (or projected) axes.
5. Optional per-node dynamics radio and time slider.

### What vidden should do

Reuse CIP-0002 pieces:

- Each node is a latent scatter (same density image + points + red
  cross, click-to-track). Not necessarily a full `latent_explorer`
  (no ARD histogram required on every node).
- Leaves use `StickView` (or a sub-skeleton variant) on a **shared**
  reconstruction pane, compositing the sub-skels as MATLAB
  `plotSubSkel` does.
- A parent modify is `predict` then `set` of child latent positions,
  then cascade. Do not rebuild figures.

### Model

GPy does not ship `HGPLVM`. This CIP may:

- wrap a duck-typed tree (`nodes` with `predict`, `X`, `children`), or
- a thin `vidden` loader around MATLAB-exported / reimplemented nodes.

Do not wait for a full GPy `HGPLVM` class to design the host. The host
depends on `predict` per node and a tree of indices.

### What this is not

A second copy of `latent_explorer` with a dropdown of nodes. Oil and
faces (CIP-0004, 0005). Correspondence / doodle studio. Referia.

Dynamics (run / slider) can be a later pass; first close is click in
the tree and see the skeleton.

## Implementation Plan

1. Specify the duck-typed tree (node `predict`, children, optional
   subskel / connect).
2. Layout: Panel grid of node scatters plus one composite `StickView`.
3. Pointer on a node updates descendants; leaves call `modify`.
4. A small synthetic tree (two leaves, one parent) as the first demo;
   CMU walk as optional later.
5. README. MATLAB `hgplvmHierarchicalVisualise` remains the visual spec.

## Backward Compatibility

No change to `latent_explorer`. New module, e.g. `vidden.host.tree`.
No MATLAB runtime.

## Testing Strategy

Cascade tests: parent `(x, y)` → child latent → leaf `Y`, without
Panel. Layout construction `importorskip`s Panel. Manual: click parent,
both leaves move.
