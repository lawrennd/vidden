## Summary

Keep the existing pytest matrix, then add the same CI hygiene GPy
already has: a Codecov upload that does not block merges, CodeQL
scanning of Python and GitHub Actions, and Dependabot for Actions and
pip.

## Motivation

CIP-0001 stood up `.github/workflows/test.yml`. That is pytest only.
Coverage, code scanning, and dependency bumps live in GPy's workflow
and `codecov.yml`; vidden should match so PRs carry the same signals.

## Detailed Description

- **Tests** stay 3.11/3.12 on Ubuntu, `[dev,explore]`, no GPy extra.
- **Coverage** is a separate Ubuntu 3.12 job: `pytest --cov=vidden`
  then `codecov/codecov-action@v7`. `codecov.yml` marks project and
  patch statuses informational so a missing Codecov token cannot fail
  the PR.
- **CodeQL** is advanced setup in `.github/workflows/codeql.yml`
  (`github/codeql-action@v4`), languages `python` and `actions`,
  `build-mode: none`. Weekly schedule plus push/PR to `main`.
- **Dependabot** weekly for `github-actions` and `pip`.
- README gains a Codecov badge next to Tests.

Do not turn on GitHub's CodeQL *default* setup as well: that would
double-scan against this workflow.

## Implementation Plan

1. Coverage job + `codecov.yml` + `pytest-cov` in the `dev` extra.
2. CodeQL advanced workflow.
3. Dependabot config.
4. README badges.

## Backward Compatibility

No runtime API change. CI stays green if Codecov is not yet linked
(`fail_ci_if_error: false`).

## Testing Strategy

Local pytest still runs without Codecov. After merge, confirm the
coverage job uploads, CodeQL appears under Security, and Dependabot
can open PRs.
