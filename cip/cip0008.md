# CIP-0008: Move doodle studio and correspondence from GPy into vidden

## Status

- [x] Proposed - Initial idea documented
- [x] Accepted - Approved, ready to start work
- [x] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented

## Summary

Move the doodle *pipeline* off GPy `notebook-latent-doodle-space` into
vidden: stroke correspondence, JSON family I/O, a drawing studio, and
an alignment check. Rebuild the two matplotlib windows as Panel apps.
Do not merge that GPy branch. Do not put matching inside the pointer
loop of `doodle_explorer`.

This implements REQ-0006 (build a family) and feeds REQ-0004 (explore
one). CIP-0003 already presents generated faces; it deferred this work
on purpose.

Work proceeds on `cip0008-doodle-studio`. The copy of this CIP on
`main` is the envisage at acceptance; later CIP edits land on that
branch.

## Motivation

vidden exists so latent demos are not trapped in GPy matplotlib.
CIP-0003 took the explorer. The paper's first half — draw a family,
match strokes, save the set — is still a matplotlib GUI on an unmerged
GPy branch. That is the same Cocoa / Jupyter failure as `visualize`.

The GPy module already has the algorithms and a disk layout. Moving
them here is the point of this repository. We keep the matcher and the
JSON. We replace `mpl_connect` with Bokeh draw tools, as CIP-0002 did
for the latent pointer.

## Detailed Description

### What moves, and what we rewrite

| GPy (`latent_doodle_space.py`) | In vidden | Form |
|---|---|---|
| `looks_closed`, `typical_template_index`, `pair_cost_and_align`, `match_to_template`, `scramble_strokes`, `align_doodles` | `vidden.doodle` | Same functions. Port tests. |
| `save_doodles` / `load_doodles` / `load_doodle_dir` / family slug | `vidden.doodle.store` (or the same module) | Same on-disk layout. Read GPy JSON. |
| `doodle_studio`, `sketch_pad`, `pick_doodles` | Panel **user** studio | Bokeh draw + gallery. Not matplotlib. |
| `plot_correspondence`, `plot_alignment` | Panel **advanced** studio | Colour-matched `DoodleView` panes. |
| `click_to_synthesize`, interpolation grid, `fit_pca_gp` | Stay out | Explorer is CIP-0003. PCA+GP is a notebook diagnostic. |
| matplotlib `visualize.py` patches | Stay out | That is why CIP-000B left the doodle branch unmerged. |

Generated faces (`FACE_STROKES`, `pack_doodle`, `make_face_dataset`)
are already here. Correspondence is not: `vidden.doodle` says so in
the module docstring.

### Matcher (no UI)

Port the GPy matcher as-is:

- Template doodle defines packed topology (`StrokeSpec` per stroke).
- Hungarian assignment (`scipy.optimize.linear_sum_assignment`) on a
  rectangular cost matrix: centroid, log-length, centred shape MSE,
  reverse and cyclic shift for closed strokes.
- Extra query strokes dropped. Unmatched template strokes packed as
  NaN. Optional `max_cost` rejects a bad pair.
- `template_index="typical"` skips a drawing with a hat or a tongue.
- Matching is parameterization, not Procrustes: a frown stays a frown.

Add `scipy` as an optional extra (`doodle`), not a hard dependency of
the package. Alignment tests `importorskip("scipy")`. The explorer
keeps working with only numpy.

Do not call the matcher on every pointer move. Align when the user
asks, or when loading a family into `doodle_explorer`.

### Disk layout

Keep the GPy family convention so existing `doodles/<family>/` copies
straight across:

```
doodles/
  faces/doodles.json
  bugs/doodles.json
  generated/doodles.json
```

JSON is the dataset. Load `format: gpy-doodle-strokes` versions 1
(no `family` key) and 2. New writes may add `format:
vidden-doodle-strokes` but must still load GPy files. PNG thumbnails
are optional; the gallery can draw strokes with `DoodleView` instead
of shipping matplotlib PNGs. If a PNG is present, the gallery may use
it.

Resolve the library relative to cwd (and an explicit path). Do not
search the GPy repository.

Saving must not shrink a longer library already on disk (GPy test
`test_save_does_not_shrink_library`).

### Two Panel apps, one store

**User studio** (`doodle_studio`):

- Left: drawing pad. Drag to add a stroke; release to finish it.
  Bokeh `FreehandDrawTool` (or `PolyDrawTool` if freehand will not
  give us a Python CDS update — CIP-0002: whole-dict assignment, not
  CustomJS `stream()`).
- Below the pad: the **selected** saved doodle in grey. Click a
  gallery item to choose it. That is the reference the user asked for.
- On the pad, a faint ghost of that same selection (or the previous
  doodle) so a family can be traced, as in GPy `plot_ghost`.
- Gallery of the current family. Buttons: Undo stroke, Clear (ghost
  stays), Keep (store and start a blank page), Save, Load.
- Family name box. Files go in `doodles/<slug>/`.
- `examples/doodle_studio.py` is `panel serve` entry.

**Advanced studio** (`doodle_align` or a mode on the same serve):

- Same family store.
- Template vs each query: same colour means the matcher put those
  strokes in the same slot; grey is a dropped extra; missing template
  strokes stay missing (NaN, not drawn at the origin — CIP-0003
  `DoodleView` already skips them).
- Optional second row: packed aligned strokes, so a frown that was
  matched then flattened is visible.
- A control to set the template (first, typical, or a gallery click).
- Packed `Y` and `StrokeSpec`s can be handed to `doodle_explorer`.

Do not make the advanced view the default serve. Correspondence is
prep. Most users only need to draw and save.

### What this is not

- Referia.
- Merging GPy `notebook-latent-doodle-space`.
- Teaching correspondence inside `latent_explorer`'s mouse loop.
- Requiring matplotlib for studio or I/O.

## Implementation Plan

1. **Port matcher and I/O** into `vidden.doodle` with the GPy unit
   tests (scramble recovery, missing NaN, extra dropped, no translate
   onto template, typical template, JSON roundtrip, save does not
   shrink). `scipy` extra.
2. **User studio** as a Panel app on Bokeh draw tools. Tests:
   construction without serving; save/load of a programmatic family;
   selected ghost is the chosen doodle.
3. **Advanced studio** from `align_doodles` + colour-mapped
   `DoodleView` / `multi_line`. Tests: assignment colours; extras
   grey; NaN strokes omitted.
4. **Examples and README**: `panel serve examples/doodle_studio.py`
   and how to open the alignment view, then `doodle_explorer` on the
   packed family. Point at GPy JSON as a loadable source.
5. Leave the GPy doodle branch unmerged. Its matplotlib studio is
   superseded here.

## Backward Compatibility

`doodle_explorer` on generated faces is unchanged. Existing GPy
`doodles.json` files load. No GPy API change. scipy is optional.

## Testing Strategy

Matcher and JSON tests without Panel, ported from
`GPy/testing/test_latent_doodle_space.py` on
`notebook-latent-doodle-space`. Studio construction
`importorskip` Panel / Bokeh. No browser driver. Manual: draw two
faces, save, reload, open alignment, then explorer.
