# CIP-0002: View and host split after the Bokeh spike

## Status

- [x] Proposed - Initial idea documented
- [ ] Accepted - Approved, ready to start work
- [ ] In Progress - Actively being implemented
- [ ] Implemented - Work complete, awaiting verification
- [ ] Closed - Verified and complete
- [ ] Rejected - Will not be implemented
- [ ] Deferred - Postponed

## Summary

Record what the GPy spike actually learned about HoloViews, Panel, and
Bokeh, and split vidden into **views** (Visualise/Modify) and a **host**
(layout, pointer, serve). CIP-0001 only moved the spike. GPy CIP-000B's
stack section is now wrong in several places. Referia is a later host,
not a dependency; design views as panes so that remains possible.

## Motivation

GPy CIP-000B chose HoloViews + Panel (Bokeh) because every mouse move
needs a Python `predict`. That choice is still the right *class* of
stack (Python callbacks, not Vega/Altair). The spike then spent days
fighting the toolkit instead of the model:

- HoloViews `PointerXY` / `Tap` on an Image overlay did not replace
  `mpl_connect`. Bokeh pan stole clicks. We attached `fig.on_event`
  on the Bokeh figure HoloViews had already built.
- Plotly-in-Panel was used as a 3-D stick. Restyle lagged the red
  cross. MATLAB never rebuilt a 3-D scene; it `set` line handles.
- Bokeh `Tap` is left-button only. Right-click is `Plot.context_menu`.
  Intercepting the browser menu did not produce a Python click.
- `ColumnDataSource.stream()` from CustomJS does not notify Python
  `on_change('data')`. Whole-dict assignment does.

Those facts belong in vidden, not as comments in a transferred file.
CIP-0001 is the package move. This CIP is the host contract.

## Detailed Description

### What CIP-0001 did not transfer

GPy CIP-000B still says:

- HoloViews `PointerXY` / `Tap` replace `mpl_connect`
- Plotly 3-D for mocap bones in the live explorer
- Widgets for dim-select (true, but incomplete: MATLAB used left/right
  mouse on the histogram)

The spike in `vidden.explore` already contradicts all three. Without
this CIP, the next person (oil, faces, doodles) will re-read 000B and
rebuild Plotly-in-Panel.

### Two layers

| Layer | Owns | Must not own |
|---|---|---|
| **View** | Artists, frozen axes, `modify(y)` data writes | Panel `servable()`, model.optimize, Bokeh menus |
| **Host** | Layout, pointer, dim-select, serve / Jupyter | Reconstruction geometry |

`StickView` is already a view: Bokeh figure + `ColumnDataSource`, cubic
limits from Visualise, `modify` only writes sources. `stick_explorer`
is a host: Panel Column, click-to-track, ARD bars, Optimize button.

The host today is HoloViz **Panel**. That is one host. It is not the
name of the package's purpose, and it is not Referia.

### Toolkit rules (from the manuals, after we ignored them)

1. **Modify is a data-source write.** Bokeh `source.data = {...}`. Not
   a new figure, not Plotly restyle, not HoloViews overlay rebuild for
   the stick.
2. **Live stick is 2-D.** Project with MATLAB's default view
   (azimuth -37.5, elevation 30). A 3-D skeleton is a later view, not
   the pointer path.
3. **Pointer events come from Bokeh, not HoloViews streams.** `tap`
   and `mousemove` on `plot.state`. Click toggles tracking (MATLAB
   `lvmClassVisualise`).
4. **`Tap` is left-click.** Right-click is `Plot.context_menu`. Python
   receives `bokeh.events.MenuItemClick` (`event.item` is the label).
   Double-click (`DoubleTap`) is the one-gesture fallback for green
   (x). Do not `preventDefault` the browser menu to fake a button.
5. **Python callbacks need a new `source.data` dict.** `stream()` from
   CustomJS does not cross to the server that way.
6. **HoloViews `framewise` is not MATLAB `cla()`.** ARD bars must
   recompute ylim after training; the stick axes must not.

### Referia: later, but the split is the design

Referia is an assessment tool (`referia serve`, FastAPI + HTMX viewer
and review form; Jupyter `Reviewer.display()` via ipywidgets). Its
"panel" is a layout region, not HoloViz Panel. It does not import
Bokeh.

We will want a latent explorer *beside* a review form at some point
(doodle families, teaching, assessment of reconstructions). That is a
later CIP, probably in referia, once vidden views are panes.

Design now:

- Views return an object a host can hold. They do not call
  `panel serve` or `servable()`.
- vidden does not import referia. referia may later depend on vidden
  (or embed a served app) the same way it does not belong inside GPy.
- Do not put FastAPI/HTMX into vidden to "match referia". Different
  interaction: Referia swaps HTML fragments; the explorer needs a
  pointer websocket to Python `predict`.
- Do not assume the Referia Jupyter ipywidgets path can host Bokeh
  events. If we embed there, we test it; we do not design as if it
  already works.

### What stays in Panel for v1

Panel remains the first host because it can sit in Jupyter and as
`panel serve`, and it can wrap a Bokeh figure whose `on_event` we
control. HoloViews stays for the grey posterior image and ARD bars,
with Bokeh hooks for clicks.

We do not switch toolkit in this CIP. We constrain how we use it.

## Implementation Plan

1. **Split the transferred module** (after Accept):
   - `vidden.views.stick.StickView` (and later image/vector)
   - `vidden.host.panel.stick_explorer` assembling panes
   - `examples/stick.py` the only `servable()` call
2. **Write the toolkit rules into the view/host docstrings** so they
   are not only in this CIP.
3. **Do not** add a referia extra, FastAPI app, or Plotly live stick.
4. Oil / faces / doodles wait until the split exists, so they land as
   views plus the same host.

## Backward Compatibility

`from vidden.explore import stick_explorer` can remain a thin import
during the split. No GPy change. Referia unchanged.

## Testing Strategy

Existing StickView tests already assert modify does not change axes.
Add: importing `vidden.views` (or today's `explore`) does not call
`servable()`. Host tests still `importorskip` Panel.
